How the agent works

The model can only talk. Our code does the work.

Claude (on Amazon Bedrock) cannot read a database or send an email. So we hand it a short menu of tools — functions it may ask us to run. It asks, we run, we report back, repeat — until it gives a final answer. That loop lives in one Java Lambda, and that is the whole agent.

The loop, in Java — 12 lines

  


while (true) {
  var res = bedrock.converse(messages, tools);
  trace.tokens += res.usage();

  if (res.stopReason() == END_TURN) break;

  for (var call : res.toolCalls()) {
    policy.check(call);
    var out = tools.run(call);
    trace.add(call, out);
    messages.add(toolResult(call.id(), out));
  }
}

    

      
converse — one AWS API call: prompt + history + tool menu in, Claude's reply out. Same format for every model.

      
usage — Bedrock returns input/output token counts on every call; that is where the cost figure comes from.

      
END_TURN — Claude says "I'm done". The other value, TOOL_USE, means "run something and come back".

      
policy.check — our rules, in code: geo premium needs a human; never guess missing fields; margin > 3% needs approval.

      
tools.run — plain Java: DynamoDB read/write, the pricing formula, SES send.

      
trace.add — one row per tool call → the agent_steps table → the Trace button.

      
toolResult — the answer goes back under the same toolUseId, so Claude knows which question it answers.

    

  






  

    
Why our own loop, not Bedrock Agents

    

      
Every tool call passes through our code — so tracing, cost, history and policy checks are a few lines in the loop, not prompt wishes.

      
Fewer moving parts — one Lambda and one API call, instead of action groups, OpenAPI schemas, aliases and versions to configure.

      
Cheaper and portable — no managed-agent overhead, no knowledge base; the loop works with any model.

      
Bedrock Agents is the right call for many agents, large document RAG, or when you want AWS to own orchestration.

    

  

  

    
What it gives the user

    

      
Trace — every tool call, with time, tokens and cost, under each agent message.

      
Decision + reason — AUTO-QUOTED / NEEDS HUMAN / RE-QUOTED / SENT, always with a why.

      
History — every field change, old → new, by agent, by Ravi, or by the shipper's email.

      
Human in the loop — the agent cannot send a quote past a policy; a person approves.
